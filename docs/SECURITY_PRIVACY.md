# Public guest demo security and privacy

The minimal safe design is **no server retention of guest cases or uploaded documents**. Setting Supabase variables does not enable persistence. No live database or deployed storage was modified.

- `persistCase()` always returns false; `storeDocument()` always returns null. Case routes validate and recompute submitted data only. PUT can return a caller's own arbitrary ID, but cannot read, update, or overwrite any stored case. The client-supplied session ID is not authorization.
- `userCaseSchema` validates nested events, action IDs, supported county/state, money, enums, dates and incompatible accepted/rejected flags. Server-side status is recomputed. Malformed input returns a generic 400; request bodies are bounded by streamed byte count, including missing or misleading Content-Length.
- The browser no longer automatically sends every saved change to the server. It stores the case in localStorage until `clearCase()` or browser-site-data deletion. Initial intake still uses an in-memory computation endpoint. Local data is neither encrypted nor protected from another person using the same browser profile. Browser/profile backups and extensions are outside HomePath's control.
- Clearing removes both case and guest session keys. No server-delete endpoint is needed for new guest data because no server record is created. **Previously stored data, if any, is not deleted by this change**; operators must inspect and remove it through an authorized process. Do not claim historic deletion has occurred.
- Real documents require multipart `consentToAIProcessing=true`, a configured Anthropic key and `Authorization: Bearer <HOMEPATH_AI_ACCESS_TOKEN>`. The token must be at least 32 characters and stays with the operator. It must never be a `NEXT_PUBLIC` variable or browser token. Public UI live extraction/drafting remains disabled; the sample is offline.
- The consent explains transfer to Anthropic, not just storage. This app does not retain the bytes or extracted result server-side. Provider processing/retention is subject to the operator's Anthropic account terms; HomePath does not claim zero provider retention. No unverified legal/privacy-policy promise was added.
- Protected AI calls have a process-wide ceiling of five calls/minute, 2,000 output tokens, 30-second SDK timeout, and no automatic retries. The private token is the primary cost boundary. The in-memory limiter resets with process restarts and is not a distributed public-access quota. Do not expose the endpoint publicly by embedding the token in UI code.
- Extraction treats document content as untrusted evidence. Dates are calendar-validated and missing fields remain null; prompt text forbids embedded instructions and calculated missing deadlines. User confirmation is still mandatory. Prompt instructions cannot guarantee perfect extraction; unreviewed output is never a legal decision.
- AI error handlers log only a route/status class, not SDK messages, file contents, names, or raw exceptions. The service-role helper is in `lib/supabaseServer.ts` with `server-only`. Guest routes do not import it.
- Reviewed resources always load locally. Optional legacy SQL tables have RLS enabled and no public personal-data policies. The schema is a setup artifact, not proof of the policies in an existing deployment.

Tests set fake Supabase credentials and a network trap to prove guest writes and resource retrieval do not contact the cloud. They also test invalid documents, missing consent/configuration, wrong token, bounded requests, rate limits, a mocked provider failure and safe error output. No paid live model request was made.

Re-enabling persistent guest data requires server-issued identity, ownership checks on every operation, deletion/retention behavior, and consent. That work is deliberately deferred rather than hidden behind an insecure environment toggle.
